# 第三阶段：边缘智能缓存优先级机制仿真实验报告

## 1. 实验目的

本实验聚焦 **边缘节点智能缓存中的优先级调度与溢出淘汰机制**。

实验目标是验证四种优先级机制是否能在缓存不足时优先保护关键观测数据。

- **更新了缓存容量设置，1GB缓存容量就足以让当前数据产生速率下产生的数据不丢失。**
- **讨论了四种不同的优先级机制，对于重要文件的保护--缓存不变的情况下，文件成功传输率相同（丢失的数据量是固定的）**

## 2. 实验目标

本次仿真实验用于回答以下问题：

1. 在**不同链路异常状态**下，数据丢失率分别是多少？**100 MB、250 MB、500 MB、1 GB 缓存容量在各链路状态下是否足够？**
2. **在缓存不足时，四种优先级机制是否能比 FIFO 更好地保护 D3/D4 关键数据？--关键数据保护率**


### 3.1 链路状态

本实验采用五类链路状态。

| Profile | 链路状态 | 阶段设置 | 实验目的 |
|---|---|---|---|
| P1 | 短时中断 | 2 Mbps 5 min -> 0 Mbps 5 min -> 2 Mbps 20 min | 验证短时中断下 100 MB 缓存是否足够 |
| P2 | 长时中断 | 2 Mbps 5 min -> 0 Mbps 20 min -> 2 Mbps 30 min | 观察长时中断下缓存容量阈值和溢出情况 |
| P3 | 严重退化 | 2 Mbps 5 min -> 0.2 Mbps 20 min -> 2 Mbps 30 min | 模拟链路未完全中断但有效吞吐严重不足 |
| P4 | 高带宽恢复 | 2 Mbps 5 min -> 0 Mbps 10 min -> 10 Mbps 20 min | 验证高恢复带宽能否快速清空缓存 |
| P5 | 波动链路 | 2 Mbps 5 min -> 0/1/0.2/0.8 Mbps 波动 20 min -> 4 Mbps 30 min | 模拟间歇可用的动态链路 |

统一数据产生速率为：

```text
data_generation_rate = 1.5 Mbps
```

当 `有效传输速率 < 数据生成速率` 时，新增数据进入边缘缓存；当缓存超过容量限制时，由对应缓存机制决定淘汰对象。

| 配置 | 缓存容量 | 
|---|---:|
| 无缓存 | 0 MB | 
| 缓存1 | 100 MB | 
| 缓存2 | 250 MB | 
| 缓存3 | 500 MB | 
| 缓存4 | 1 GB | 

### 3.3 数据类型与优先级映射

为了保证五类数据同时竞争缓存空间，D1-D4 四类文本/传感器数据采用相同产生速率；视频文件 V1 由于体积更大，设置为更高产生速率。总速率保持 `1.5 Mbps`。

| 数据流 | 数据类型 | 速率 | 初始等级 | 
|---|---|---:|---:|
| D1 | buoy weather | 0.25 Mbps | P2 |
| D2 | weather UTF-16 | 0.25 Mbps | P2 | 
| D3 | wave sensor | 0.25 Mbps | P1 | 
| D4 | current logs | 0.25 Mbps | P1 | 
| V1 | video file | 0.50 Mbps | P3 | 

**具体实现：同一时间段内生成的D1, D2, D3, D4, V1数据从按顺序抵达。**

**D3 和 D4 被视为关键数据，用于计算关键数据丢失率**。

## 4. 缓存机制实现

### 4.1 FIFO 缓存基线

**机制说明：** 数据按到达顺序进入缓存，链路恢复后按到达顺序补传。缓存满时优先丢弃最新进入但无法容纳的数据。

**作用：** FIFO 不区分数据重要性，用于衡量普通缓存机制在容量不足时的关键数据保护能力。

### 4.2 机制一：固定等级优先级队列

**机制说明：** 按文件类型直接分配 P0-P3 等级。链路异常时数据进入等待队列；链路恢复后先发送高优先级队列；缓存满时从最低优先级队列开始淘汰。

```text
发送顺序：P0 -> P1 -> P2 -> P3
淘汰顺序：P3 -> P2 -> P1 -> P0
同级内部：FIFO（进一步细化补充非原论文内容）
```

**参考依据：** J. Burgess, B. Gallagher, D. Jensen, and B. N. Levine,
“MaxProp: Routing for Vehicle-Based Disruption-Tolerant Networks,”
Proceedings of IEEE INFOCOM, 2006.

### 4.3 机制二：固定等级 + 防饥饿机制

**机制说明：** 在固定等级基础上加入等待时间因子。低优先级文件等待过久后临时提升发送分数，避免低优先级数据永久无法补传。

```text
if waiting_time_i > α_prom × average_waiting_time:
    priority_i = min(priority_i + 1, Pmax)
    waiting_time_i = 0
```

- 等待的时间超过一定阈值后提高文件的优先级

**参考依据：**  Becker T, Schüle T. Evaluating Dynamic Task Scheduling with Priorities and Adaptive Aging in a Task-Based Runtime System. In: ARCS 2020, Lecture Notes in Computer Science, vol. 12155, pp. 17–31. DOI: 10.1007/978-3-030-52794-5_2

### 4.4 机制三：动态等级 -- 基于原始优先级按时间戳改变优先级

**机制说明：** 
在固定优先级上引入，新鲜度--衡量数据的新旧程度（考虑不同的数据的实效性，一些实时性较强数据在较长时间丢失后，其数据就没太大意义了不如传新的）。

```text
age_seconds = current_time - timestamp
freshness = max(0, 1 - age_seconds / ttl_seconds)
score = 100 * priority_weight + 40 * event_flag + 30 * freshness - 5 * size_MB
```

- event flag表示在这一段时间提供标记文件的优先级。
- age_seconds 表示该类数据产生了多久了。
- ttl_seconds 表示该类数据的新鲜度有效窗口，用于控制新鲜度衰减速度。
- priority_weight 根据静态优先级设定，不同优先级值不同。

最终 score 为动态优先级分数，发送时优先选择高分数据，缓存溢出时优先淘汰低分数据。

**参考依据**：Corneo et al., Age of Information-Aware Scheduling for Timely and Scalable Internet of Things Applications
来源：IEEE INFOCOM, 2019，CCF-A


### 4.5 机制四：动态等级 -- 未预先设置优先级，效用-空间成本优先机制

**机制说明：** 文件是否值得占用缓存空间”转化为单位空间效用评分。文件进入缓存前先计算单位空间价值，优先缓存“价值高、体积小、时效强”的数据。

```text
utility = 60 * event_flag + 30 * scientific_value + 20 * freshness + 10 * waiting_factor
cost = log2(size_MB + 1)
score = utility / cost
```

- utility由该数据是否处于关键事件窗口event_flag、科研价值（实验中也是按照静态优先级给不同的权重）scientific_value、新鲜度freshness和等待时间组成，表示该数据被保留和优先发送的收益。
- cost = log2(size_MB + 1) 表示其占用缓存空间的代价。
- score = utility / cost 衡量单位缓存空间能带来的价值，越大优先级越高。


**参考依据：** Alcoz et al., *Everything Matters in Programmable Packet Scheduling*, NSDI 2025，CCF-A。


## 5. 仿真实现

仿真脚本采用 10 s 离散时间步长。每个时间步执行以下逻辑：

1. 按各数据流速率生成新数据块。
2. 根据当前链路 Profile 和时间点计算可发送数据量。
3. 如果链路能力不足，剩余数据进入边缘缓存。
4. 如果缓存超过容量限制，根据缓存策略选择淘汰对象。
5. 恢复阶段继续传输新数据，并按策略补传缓存数据。

## 6. 评价指标

| 指标 | 计算方式 | 含义 |
|---|---|---|
| 关键数据丢失率 | `(D3_dropped + D4_dropped) / (D3_produced + D4_produced)` | 衡量关键观测数据保护能力、核心完整性指标 |
| 缓存溢出/数据丢失率 | `overflow_mb（dropped_mb ） / produced_mb ` | 有缓存策略下，缓存溢出数据即视为永久丢失 |
| 数据送达率 | `delivered_mb / produced_mb` | 最终成功送达比例 |

- 恢复系数这个指标确实没什么含义我认为可以去掉，**因为这个完全取决于，恢复时期的链路状态**。
比如：根据链路状态，实际能传输的数据量 = 求和（时间段长度 * 时间段内的链路状态）
- 只计算数据丢失率就行了**探索如何设计缓存大小**
- 衡量重要数据是否保存**优先级机制对关键数据的保护情况--关键数据丢失率**

## 8. 新链路状态说明

`dynamic-link-config` 文件夹中的新链路状态来自 `dynamic-link-fluctuation.csv`，用于描述 60 min 内海缆链路的连续动态变化。该配置不是 P1-P5 这种离散人工场景，而是 30 s 粒度的时序链路：共有 120 个实际执行片段，`time_min=60.0` 仅作为绘图终点，不执行额外片段。

新链路配置中，`capacity_mbps` 在全部片段中固定为 2 Mbps，动态变化主要体现在 `rtt_ms`、`packet_loss_rate` 和 `severity`。如果在当前缓存仿真中使用该链路，可以按以下方式折算链路有效传输速率：

```text
effective_mbps = capacity_mbps * (1 - packet_loss_rate)
```

按时间和链路质量变化趋势，可以将该新链路粗略分成三段：

| 粗分阶段 | 时间范围 | 原始 phase | 平均有效吞吐 | 最小有效吞吐 | 平均 RTT | 最大 RTT | 平均丢包率 | 最大丢包率 |
|---|---:|---|---:|---:|---:|---:|---:|---:|
| S1 正常至逐步退化 | 0-24 min | normal start、gradual degradation | 1.862 Mbps | 1.677 Mbps | 131.9 ms | 200.5 ms | 6.89% | 16.15% |
| S2 严重波动 | 24-42 min | bad variable link | 1.757 Mbps | 1.687 Mbps | 172.7 ms | 197.5 ms | 12.17% | 15.64% |
| S3 恢复至正常 | 42-60 min | gradual recovery、normal end | 1.860 Mbps | 1.673 Mbps | 132.8 ms | 202.7 ms | 7.02% | 16.36% |

从链路质量看，三段划分是有意义的：S1 表示从正常链路逐步退化，S2 表示高 RTT 和高丢包的严重波动期，S3 表示链路逐步恢复。但从当前缓存实验参数看，该新链路未必能直接用于比较四种优先级机制，因为其最小有效吞吐约为 1.673 Mbps，仍高于当前数据产生速率 1.5 Mbps。

因此，如果直接把该新链路接入当前缓存仿真，可能不会产生缓存积压和淘汰事件，也就无法判断哪种优先级机制更能保护 D3/D4 关键数据。若要用这组三段链路状态比较优先级机制，需要进一步构造压力条件，例如提高数据产生速率，或将 `severity` 映射为带宽下降，使部分时间段满足 `effective_mbps < data_generation_rate`。

## 附录：优先级策略参数设置

本附录说明四种优先级缓存策略在仿真中的具体参数取值。所有策略均使用相同的数据流设置，只改变发送顺序和缓存溢出时的淘汰规则。

### A.1 数据流基础参数

| 数据流 | 初始等级 | priority_weight | scientific_value | ttl_seconds | event_flag 设置 | 说明 |
|---|---:|---:|---:|---:|---|---|
| D1 | P2 | 2 | 0.60 | 600 | 始终为 0 | 常规背景气象观测 |
| D2 | P2 | 2 | 0.55 | 600 | 始终为 0 | 常规背景气象文本 |
| D3 | P1 | 3 | 0.95 | 300 | 14-20 min 为 1，其余为 0 | 关键波浪观测 |
| D4 | P1 | 3 | 0.90 | 300 | 16-22 min 为 1，其余为 0 | 关键海流观测 |
| V1 | P3 | 1 | 0.10 | 1800 | 始终为 0 | 普通视频文件 |

参数解释：

- `priority_weight` 用于把 P1/P2/P3 映射为数值权重，P1=3、P2=2、P3=1。
- `scientific_value` 表示科研/业务价值，D3/D4 最高，D1/D2 居中，V1 最低。
- `ttl_seconds` 表示数据新鲜度衰减窗口，关键实时观测 D3/D4 设置为 300 s，常规气象 D1/D2 设置为 600 s，普通视频 V1 设置为 1800 s。
- `event_flag` 用于模拟关键事件窗口。由于原始数据没有真实异常标签，仿真中只对 D3/D4 设置确定性事件窗口。

### A.2 Priority-SP：固定等级优先级队列

Priority-SP 不计算连续分数，只使用固定等级排序。

```text
发送顺序：P1 -> P2 -> P3
淘汰顺序：P3 -> P2 -> P1
同级内部：FIFO
```

本实验中没有 P0 数据，因此最高等级从 P1 开始。该策略用于验证最简单的文件类型优先级是否足以保护 D3/D4。

### A.3 Priority-Aging：固定等级 + 防饥饿机制

Priority-Aging 在固定等级基础上加入等待时间奖励。

```text
aging_bonus = min(30, 10 * waiting_minutes)
score = 100 * priority_weight + aging_bonus - 5 * size_MB
```

参数设置：

| 参数 | 取值 | 含义 |
|---|---:|---|
| `priority_weight` | P1=3，P2=2，P3=1 | 固定优先级主权重 |
| `aging_bonus` 增长率 | 每等待 1 min 增加 10 | 让低优先级数据等待越久分数越高 |
| `aging_bonus` 上限 | 30 | 防止普通视频仅因等待过久超过关键数据 |
| `size_MB` 惩罚系数 | 5 | 大文件在缓存竞争中略降权 |

发送和淘汰均按 `score` 排序：发送时选择分数最高的数据，淘汰时选择分数最低的数据。

### A.4 Priority-AoI：新鲜度优先机制

Priority-AoI 使用时间戳和 TTL 计算数据新鲜度，不再使用变化率因子。

```text
age_seconds = current_time - timestamp
freshness = max(0, 1 - age_seconds / ttl_seconds)
score = 100 * priority_weight + 40 * event_flag + 30 * freshness - 5 * size_MB
```

参数设置：

| 参数 | 取值 | 含义 |
|---|---:|---|
| `priority_weight` | P1=3，P2=2，P3=1 | 固定优先级基础权重 |
| `event_flag` 权重 | 40 | 事件窗口数据额外加分 |
| `freshness` 权重 | 30 | 越新的数据分数越高 |
| `size_MB` 惩罚系数 | 5 | 大文件略降权 |
| `ttl_seconds` | D1/D2=600，D3/D4=300，V1=1800 | 新鲜度衰减窗口 |

该策略适合实时状态类数据。D3/D4 的 TTL 更短，表示关键海洋状态数据对时效性更敏感。

### A.5 Priority-Utility：效用-空间成本优先机制

Priority-Utility 先计算数据效用，再除以空间成本，并结合缓存水位对普通视频 V1 施加惩罚。

```text
wait_factor = min(1, waiting_minutes / 10)
utility = 60 * event_flag + 30 * scientific_value + 20 * freshness + 10 * wait_factor
cost = log2(size_MB + 1)
score = utility / cost
```

参数设置：

| 参数 | 取值 | 含义 |
|---|---:|---|
| `event_flag` 权重 | 60 | 事件数据优先保留 |
| `scientific_value` 权重 | 30 | 科研/业务价值越高分数越高 |
| `freshness` 权重 | 20 | 新鲜数据优先保留 |
| `wait_factor` 权重 | 10 | 等待越久略微加分 |
| `wait_factor` 上限 | 1 | 等待 10 min 后达到上限 |
| `cost` | `log2(size_MB + 1)` | 文件越大，单位空间效用越低 |

缓存水位惩罚设置：

| 条件 | 分数调整 | 含义 |
|---|---:|---|
| V1 普通视频 | -150 | 普通视频默认低于关键文本数据 |
| 缓存水位 >= 70% 且为 V1 | 额外 -100 | 缓存开始紧张时降低普通视频保留概率 |
| 缓存水位 >= 85% 且为 V1 | 额外 -300 | 缓存高度紧张时更积极淘汰普通视频 |
| 缓存水位 >= 95% 且非关键/非事件数据 | 额外 -500 | 极端紧张时只保护关键和事件相关数据 |

该策略主要用于模拟“视频文件较大、关键文本更重要”的取舍逻辑。本实验中 V1 产生速率较高且优先级较低，因此在小缓存场景下会承担更多丢弃压力。
