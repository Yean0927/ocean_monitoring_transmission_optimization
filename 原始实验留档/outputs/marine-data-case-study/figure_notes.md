# 图 2：资源敏感性对照及 QA

## 论证与数据

图用于回答：完成文件的压缩、网络传输与解压缩时间如何响应 RTT、带宽和 CPU 变化。

- 面板依次为 Text (D2)、Video (V1)、Image (I1)。
- 横轴 Poor / Medium / Good；Delay / BW / CPU 三条曲线的配置见 case_study.md 表 I。
- 每类数据九个点，共 27 点；每点五次技术重复，均值 ± 样本标准差。
- 数据来自 45 组实际压缩、解压缩测量，以及最终 135 次 ns-3 TCP CUBIC 文件传输仿真。
- 相同处理重复在 Delay、BW 与 CPU-Medium 间配对复用；不能把各点视为互相独立的总体样本。
- JCT 从 N1 完整文件可用计至 N3 解压缩完成，不含源端采集与聚合等待。
- CPU 的共享条件为 0.5 CPU-s/s 软件配额模拟；视频线程池随 1/4 vCPU 设置调整，文本和图像保持单线程。
- 实际字节和网络事件全部可追溯。没有采用大小/带宽代替新图中的 TCP 传输时间。
- 修正原 RTT 毫秒截断后重新完成全部网络对照；初次诊断结果不参与本图。

结果支持本工况下文本对 RTT 的响应、视频对 CPU 和带宽的响应，以及图像对网络资源的响应。没有强行将三类数据分别分配给三种资源。误差棒可能小于标记尺寸，曲线也可能重合，均保留真实数值。

## 输出

Python/matplotlib；180 × 78 mm，三个面板纵轴均为秒，独立线性缩放。图例固定黑色菱形实线 Delay、粉色圆点虚线 BW、蓝色三角点线 CPU。PDF/SVG 保留可编辑文字，PNG 300 dpi，TIFF 600 dpi。

数据源：resource-experiment/summary.json 与 trials.json；导出的 figures/resource_source_data.json 保存全部 27 个点、均值和标准差。
