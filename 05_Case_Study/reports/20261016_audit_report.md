# Case study 与消融实验共用缺陷审计

审计日期：2026-10-16。

**结论：当前论文使用的资源敏感性 case study 不需要因本次消融实验发现的错误重跑。** 当前图表取自独立的 TCP CUBIC 单对象试验。历史 FULL/QUIC 示例另行保留，不属于本结论的有效证据范围。

## 逐项判断

| 消融实验问题 | case study 中的实际路径 | 当前结果是否需要重跑 |
|---|---|---|
| QUIC 退避把乘方写为按位异或 | 正式入口指定 `WO_PROTOCOL`；135 条实际轨迹及决策均为协议 2，即 TCP CUBIC | 不需要；未执行该发送/重传路径 |
| QUIC 发送缓冲可用空间无符号下溢 | 正式传输使用 TCP socket；挂载 QUIC 服务端不等于发送数据经过 QUIC | 不需要 |
| QUIC RTO 包号边界和 ACK 批量重置错误 | 正式 TCP 连接不调用 QUIC 恢复代码 | 不需要 |
| Priority-MaxF 按流下标分配 Zipf 权重，与报告顺序不符 | `resource-simulator.cc` 的 `Score` 确实仍有同一实现；每次只有一个文件，无候选间排序与缓存淘汰 | 本设计不受影响；将来做多对象竞争时须先修正 |
| RTT/2 的毫秒整数截断 | 正式独立源码已使用 `Seconds(l.rtt/2000.0)`；此前已完成全部 135 次网络重跑 | 不需要再次重跑 |
| 每组没有重复实验 | 45 组实际处理测量、135 次网络仿真，每点 5 次技术重复 | 已有重复；仅代表同一对象的测量变异，不能解释成不同海洋样本的总体变异 |

## 本次直接验证

- 检查全部 135 次正式输入、逐文件 trace、协议决策、链路设置及结束日志，均只有 1 个文件、协议 2、完整送达；全部链路丢包计数与等待队列峰值、截止队列均为 0。
- 最大 JCT 为 23.760401765 s，均在 3600 s 截止前完成。按 trace 时间戳重新核对压缩、传输、解压缩和 JCT 的关系，未见异常长停顿。
- 核对 45 组原始/压缩文件的 SHA-256、字节数和处理时间记录；文本再次逐字节解压比较通过，15 组压缩视频保存的完整解码记录均为 505 帧。本次未重新计时压缩或重做视频解码。
- 从正式 trace 重新核对全部 27 个均值、样本标准差及分项均值。`figures/resource_source_data.json` 与 `figures/layout_figures/resource_source_data.json`（原 LaTeX 配图目录，已迁移） 均与正式汇总一致。
- 正式仿真源码和二进制的当前 SHA-256 与原 `run-config.json` 记录一致。
- 选择每类对象各 3 种场景：Delay/Poor、BW/Good、CPU/Poor，均取 rep-0，共 9 个输入场景。使用原 case study 二进制，分别加载公共动态库与最新五种子消融实验使用的修复 QUIC 动态库，共执行 **18 次独立复现**。
- 18 次复现的完整 trace 字段、协议决策及链路计数均与对应正式结果完全相同。修复库加载通过动态加载器日志核实，其 SHA-256 与修复版消融 provenance 一致。此验证覆盖 9 个选定场景；不是把全部 135 次试验重新运行一遍。

复现输入沿用原真实压缩产物与实测处理时间，因此只验证网络事件重放与更换 QUIC 库的影响，不视为新的 CPU 技术重复。

## 应处理的历史与复现隐患

1. `case_measurements.json` 的 `actual_full_events` 保存 D2/31、V1/4335、I1/3607 三个旧 FULL 事件，经查原 `results/FULL.csv`，三者实际协议均为 0，即 QUIC。若论文仍使用这些事件的耗时，应从同一修复版系统结果中重新提取并核对；不能沿用旧数值。当前正式正文生成器读取 `summary.json` / `trials.json`，未使用这些旧事件。该 JSON 在正式试验中只用作代表对象选择清单。
2. `build_case_study.py` 在有 `resource-experiment/summary.json` 时跳转至新版生成器；若该汇总不存在，则回退到旧 FULL 结果和大小/带宽名义计算。重新建目录时应明确区分这条历史分支。旧 `bandwidth_case_study` 图属于名义计算，不是正式 TCP 资源敏感性试验的替代证据。
3. `run_resource_experiment.py:142` 仅凭 `trace.csv` 存在即跳过网络执行；`controlled_worker` 也缺少完整的输入、处理配置和软件版本缓存校验。主函数还会先写入当前 `run-config.json`。将来修改程序后直接运行可能沿用旧结果并更新配置记录。**当前未发现结果与输入不一致，但今后复跑应使用全新结果目录，或先增加逐试验配置指纹与完成标记。**
4. 原正式配置记录了二进制与源码哈希，没有固定运行时动态库哈希。本次修复库替换试验支持当前结论；今后正式运行应同时保存实际加载库的版本及哈希。

本次仅新增审计脚本、审计报告和隔离复现目录，没有修改正式试验数据、论文文字、图表或原实验代码。
