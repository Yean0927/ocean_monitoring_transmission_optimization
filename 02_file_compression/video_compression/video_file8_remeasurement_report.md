## 新计算结果

设原始文件大小为 S0 bytes，平均输出大小为 Sc bytes，平均编码与解码时间之和为 C 秒，带宽 B 的单位为 Mbps：

```text
T_direct(B) = 8*S0 / (1e6*B)
T_video(B) = C + 8*Sc / (1e6*B)
R(B) = 100*(T_direct - T_video)/T_direct
     = 100*(1 - Sc/S0) - 100*C*1e6/(8*S0)*B
```

R 的单位为 %。不先对中间时延或点值四舍五入；仅展示时保留两位小数。

| 方案 | 2 Mbps | 4 Mbps | 10 Mbps |
|---|---:|---:|---:|
| S0 原始直传 | 0.00% | 0.00% | 0.00% |
| S1 H.264 降码率 | 83.44% | 81.68% | 76.40% |
| S2 H.265/HEVC | 82.65% | 76.56% | 58.30% |
| S3 AV1 | 18.73% | −51.78% | −263.31% |

由完整精度的均值代入，得到以下直线表达式（下式系数仅为展示而截断）：

```text
S0: R(B) = 0
S1: R(B) = 85.2005748705 - 0.8801807524*B
S2: R(B) = 88.7346070125 - 3.0437655998*B
S3: R(B) = 89.2381751655 - 35.2543583218*B
```

三种压缩方案的 2→4 与 4→10 Mbps 两段斜率之差均小于 1e-13；中间点偏离端点直线的最大值约 1.42e-14 个百分点，仅为浮点计算误差。图上直接连接三个独立代入公式的点，没有手动移动中间点，也没有对旧图做强制直线拟合。
